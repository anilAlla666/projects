I can't see the current tests for `_get_system_details`, so I'm writing a new self-contained test file that exercises it directly.

The issue's example output is `CHARMCRAFT_AUTH='<hidden>'`. The exact placeholder is left open ("something like"), so the tests do not assert on it. They check the following:
- When `CHARMCRAFT_AUTH` is set, its name appears in the output.
- The secret value never appears in the output.
- When `CHARMCRAFT_AUTH` is not set, the output does not mention it.
- Other `CHARMCRAFT_*` variables are still logged with their values.

`ALTERNATE_AUTH_ENV_VAR` is imported from `charmcraft.commands.store.client`, as the existing tests do.

On the current code, the first test fails because the variable name is not logged at all.

+import os
+from unittest.mock import patch
+
+from charmcraft.commands.store.client import ALTERNATE_AUTH_ENV_VAR
+from charmcraft.main import _get_system_details
+
+
+def _clean_environ(extra):
+    base = {k: v for k, v in os.environ.items() if not k.startswith("CHARMCRAFT")}
+    base.update(extra)
+    return base
+
+
+def test_auth_presence_logged_without_value():
+    secret = "super-secret-credentials-value"
+    env = _clean_environ({ALTERNATE_AUTH_ENV_VAR: secret})
+    with patch.dict(os.environ, env, clear=True):
+        result = _get_system_details()
+    assert ALTERNATE_AUTH_ENV_VAR in result
+    assert secret not in result
+
+
+def test_auth_absent_not_logged():
+    env = _clean_environ({})
+    with patch.dict(os.environ, env, clear=True):
+        result = _get_system_details()
+    assert ALTERNATE_AUTH_ENV_VAR not in result
+
+
+def test_other_charmcraft_vars_still_logged_with_auth():
+    secret = "super-secret-credentials-value"
+    env = _clean_environ({ALTERNATE_AUTH_ENV_VAR: secret, "CHARMCRAFT_OTHER": "visible"})
+    with patch.dict(os.environ, env, clear=True):
+        result = _get_system_details()
+    assert "CHARMCRAFT_OTHER='visible'" in result
+    assert ALTERNATE_AUTH_ENV_VAR in result
+    assert secret not in result
