I added a test file for the dotted artifact-id case. I haven't run it. It assumes the function is `tools.get_brew_url(md5)`, since the start of that function wasn't in the excerpt. It also assumes `get_brew_url` calls `subprocess.check_output` twice, first for `listArchives` and then for `getBuild`. I mocked both calls with the `javax.json` data from the issue.

The first test checks that the URL keeps the dot in the artifact id (`.../org/glassfish/javax.json/1.0.4/javax.json-1.0.4.jar`) rather than turning it into `javax/json`. It should fail on the current code. The second test is a guard: a dotted group id should still become slashes while a plain artifact id stays unchanged, and it should pass before and after the fix.

+from cekit import tools

+def _mock_brew(mocker, archive, build):
+    return mocker.patch(

+        "id": 863130,
+    }
+    build = {"state": 1, "package_name": "org.glassfish-javax.json", "release": "1"}
+
+    _mock_brew(mocker, archive, build)
+
+    url = tools.get_brew_url("569870f975deeeb6691fcb9bc02a9555")
+

+        "/maven/org/glassfish/javax.json/1.0.4/javax.json-1.0.4.jar")
