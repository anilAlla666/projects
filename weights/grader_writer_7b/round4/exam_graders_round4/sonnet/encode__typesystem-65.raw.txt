The fix is to make `ValidationError` hashable, so the tests check that `hash()` works and that `traceback.print_exc()` runs. I haven't run them.

The tests avoid any particular hash value. They only require that `hash()` doesn't raise and that equal errors hash equally. That equality requirement is the standard hash contract and holds for any reasonable fix.

`ParseError` shares `BaseError`, so it gets a hash test too. Its `__eq__` only matches `ValidationError`, so I don't assert anything about equal `ParseError`s.

- **Traceback test:** it calls `traceback.print_exc()` inside an `except` block, writing to a `StringIO` via `file=`.
- **Python 3.6 gap:** the 3.6 bug is in how the traceback code tracks exceptions it has already seen. On newer Pythons `print_exc` may pass even without the fix, so the `hash()` tests are the ones that fail on current code on any version.
- **Chained exceptions:** a second traceback test raises a `ValidationError` as the cause of another exception, which exercises hashing on newer versions too.
