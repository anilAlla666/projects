I could not see the repository, so this test is written against my recollection of `redpocket/api.py` and has not been run. I assumed `RedPocket` exposes `get_line_details(...)` and that it sends the `/account/get-details` request through a `requests.Session` stored as `self.session`. If either assumption is wrong, the test needs adjusting.

To avoid depending on the constructor's login flow, the test builds the client with `__new__` and attaches a plain `requests.Session`. It patches `HTTPAdapter.send`, so it does not matter which `Session` method the code calls. It records the outgoing request and asserts that the query string contains `type=api` alongside the line id. The current code does not send `type=api`, so the test fails there and should pass once the fix adds it.
