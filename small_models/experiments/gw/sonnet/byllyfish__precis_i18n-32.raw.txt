I haven't run these tests, and I didn't see the repository's existing test layout, so I put them in a new file. The new file is `tests/test_nickname_whitespace.py`.

- **What the tests check:** After the fix, control characters such as `\x1f` and `\t` should no longer be stripped from the ends of a nickname. Enforcement should raise an error instead. Plain ASCII spaces should still be stripped, and non-ASCII `Zs` spaces should still be converted to a space and then stripped.
- **What the tests leave out:**
  - I left out `\n` and `\r\n`, because the issue says `\n` might keep being stripped for compatibility.
  - I don't assert the exact `invalid_white_space` message. I couldn't confirm which exception type or message format the fix will use, so I only check for `ValueError` (which `UnicodeEncodeError` subclasses).

+import pytest
+
+from precis_i18n import get_profile
+
+
+@pytest.fixture
+def nickname():
+    return get_profile("Nickname")
+
+
+def test_strip_ascii_space(nickname):
+    assert nickname.enforce("  a  ") == "a"
+
+
+def test_strip_zs_space(nickname):
+    # Non-ASCII Zs is mapped to ASCII space, then stripped.
+    assert nickname.enforce("\u2003a\u00a0") == "a"
+
+
+@pytest.mark.parametrize(
+    "value",
+    [
+        "\x1fb\x1f",
+        "\x1fb",
+        "b\x1f",
+        "\tc",
+        "c\t",
+        "\x0bc\x0c",
+        "\x1cd\x1d\x1e",
+    ],
+)
+def test_control_whitespace_not_stripped(nickname, value):
+    with pytest.raises(ValueError):
+        nickname.enforce(value)
