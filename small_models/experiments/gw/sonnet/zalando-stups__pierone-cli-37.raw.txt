It assumes `get_clair_features` is called as `(clair_url, clair_id, token)`, as in the traceback, and that `pierone/cli.py` fetches the layer with `requests.get`. If it uses another HTTP call, the monkeypatch target needs adjusting.

The test feeds `get_clair_features` a Clair layer response with no `Features` key, which is what a `COULDNT_FIGURE_OUT` layer returns. On the current code it raises `KeyError`. After the fix it should return an empty list. A second test checks that a response with features still returns them.

+from unittest.mock import MagicMock
+
+from pierone.cli import get_clair_features
+
+
+def _response(payload):
+    resp = MagicMock()
+    resp.status_code = 200
+    resp.json.return_value = payload
+    return resp
+
+
+def test_get_clair_features_without_features_key(monkeypatch):
+    # Clair returns a layer without "Features" when the status is COULDNT_FIGURE_OUT
+    payload = {'Layer': {'Name': 'sha256:abc', 'NamespaceName': 'debian:8', 'IndexedByVersion': 2}}
+    monkeypatch.setattr('requests.get', MagicMock(return_value=_response(payload)))
+
+    features = get_clair_features('https://clair.example.org', 'abc', 'tok')
+
+    assert not features
+    assert list(features) == []
+
+
+def test_get_clair_features_with_features(monkeypatch):
+    feats = [{'Name': 'openssl', 'Version': '1.0'}]
+    payload = {'Layer': {'Name': 'sha256:abc', 'Features': feats}}
+    monkeypatch.setattr('requests.get', MagicMock(return_value=_response(payload)))
+
+    assert get_clair_features('https://clair.example.org', 'abc', 'tok') == feats
