I couldn't run these tests. They assume `resolve_security_groups(security_groups, region)` in `senza/aws.py` calls `boto3.resource('ec2', region)` and then `ec2.security_groups.filter(Filters=...)`. I wrote that from memory of senza's code, not from the repository, so check it before relying on the tests.

The tests use a fake EC2 resource whose `filter` returns different groups depending on whether the filter is a tag `Name` lookup or a `group-name` lookup. A tag lookup is recognised either as `tag:Name` or as `tag-key=Name` plus `tag-value`.

- **Tag lookup:** a group matched only by its `Name` tag must resolve to its ID. This fails on the current code, which only filters by `group-name`.
- **Tag preferred:** when the tag and the generated group name point to different groups, the tag match wins. This also fails on the current code.
- **Fallback:** a name that matches only by `group-name` still resolves. This should already pass today and guards against regressions.
- **Not found:** a name that matches nothing raises `ValueError`. This should also pass today.
- **Passthrough:** `sg-…` IDs and dict entries are returned as they are, without any lookup.
