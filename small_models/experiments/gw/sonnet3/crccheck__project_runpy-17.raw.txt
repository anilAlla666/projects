I'm adding tests for the case where `sql` is `None` in the record args. Django can log such a record, for example when `executemany` is called with no SQL. The issue only requires that `filter` no longer raises, so the tests check that it doesn't raise and that the record is still allowed through (`filter` returns truthy). I don't assert anything about what `record.args` becomes, since the issue leaves that open.

I considered whether to also test `args` of the wrong shape, but the issue doesn't mention it, so I left it out. I also chose not to assert that `record.args[1]` stays `None`, because a fix might handle it differently. Checking only that `filter` returns truthy is enough.

I haven't run these tests against the current code or a fix.
