I'm adding tests to `tests/test_base.py`. They have not been run here. The fix adds `__hash__` to `BaseError`, so the tests check hashability and the `traceback.print_exc()` case from the issue, without assuming a particular hash value.

The tests are:
- `test_validation_error_is_hashable` calls `hash()` on a `ValidationError`, which raises `TypeError` on the current code.
- `test_validation_error_hash_consistent_with_eq` checks that two equal errors have equal hashes, which Python requires of any `__hash__` alongside `__eq__`.
- `test_validation_error_usable_in_set` puts an error in a set, which also needs hashing.
- `test_validation_error_print_exc` runs the code from the issue. It uses `traceback.format_exc()` instead of `print_exc()` and checks that the exception text appears in the output. It does not depend on the Python 3.6 bug, so it may already pass on newer Pythons. It stays as a regression check.
- `test_parse_error_is_hashable` covers the other `BaseError` subclass. `ParseError` has the same missing `__hash__`, so the fix should apply to it too.
