The diff below adds a new test file, `tests/test_synced_dict_no_mutation.py`. I have not run it. The tests use only the public job API and do not assume whether `values()` and `items()` return synced or plain nested dicts.

The tests check that:
- `job.sp.a` and `job.doc.a` keep their type, and are the same object, after `keys()`, `values()` and `items()`.
- The contents returned by `values()` and `items()` are still equal to the expected nested dicts.
- Writing `job.doc.a.b = 'd'` after `values()` still works and persists when the job is reopened. On the current code this fails because `job.doc.a` has already been replaced by a plain `dict`.
