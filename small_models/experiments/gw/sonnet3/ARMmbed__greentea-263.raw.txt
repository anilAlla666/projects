I've added a new test file that calls `create_filtered_test_list` with wildcards in different positions. I haven't run it against the current code or a fix. On the current code, the leading, middle and multi-wildcard cases should fail because only a trailing `*` is handled. The trailing-star and exact-name cases are regression guards and should pass before and after.

The tests use only `*` as the wildcard, since the issue doesn't pin down other `fnmatch` syntax. They also assume `create_filtered_test_list` returns the filtered dict and accepts `''` for `skip_test`, because the code after the filtering step was cut off in what I was given.
