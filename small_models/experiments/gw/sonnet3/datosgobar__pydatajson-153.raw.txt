I've added a `HarvestCatalogTestCase` to `tests/test_federation.py`. I haven't run the tests against the current code or a fix. The tests mock `harvest_dataset_to_ckan`, so no CKAN portal is involved.

- **Empty list:** `dataset_list=[]` must not call `harvest_dataset_to_ckan` at all. This fails on the current code, which federates every dataset.
- **Failure in the middle:** with the middle dataset raising, `harvest_catalog_to_ckan` must not propagate the exception and must still attempt all three datasets. This fails on the current code, which raises.
- **All fail, no list:** when every call fails and no `dataset_list` is passed, nothing is raised and every catalog dataset is attempted.

The tests deliberately do not check the return value or how the error is logged. They only count calls, and the test names the datasets explicitly so it does not depend on the sample catalog contents.
