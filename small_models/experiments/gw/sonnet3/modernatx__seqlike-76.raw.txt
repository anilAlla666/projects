This diff adds two tests to `tests/test_codon_tables.py`. I have not run them. They assume `python_codon_tables.get_codons_table()` returns a cached object, as the issue describes. In that case the module-level tables in `seqlike.codon_tables` are the cached objects themselves, so the tests should fail on the current code and pass once the tables are copied.

- **`test_module_tables_do_not_leak_into_pct`:** adds `"-"` and `"X"` entries to a seqlike table, then checks that a fresh `get_codons_table()` call does not contain them. It removes the entries afterwards so a failure does not pollute other tests.
- **`test_pct_mutation_does_not_affect_module_tables`:** adds an entry to a table obtained directly from `python_codon_tables`, then checks that the seqlike tables are unaffected.

Both tests use the public `python_codon_tables` API and the `human_codon_table`, `yeast_codon_table` and `ecoli_codon_table` names that `seqlike.codon_tables` already exports. They do not depend on how the copy is implemented.
