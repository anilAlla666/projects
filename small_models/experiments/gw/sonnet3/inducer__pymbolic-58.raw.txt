The patch below adds one test that fails on the current code (the `ParseError` from the issue) and should pass once the condition of `if`/`else` accepts logical operators. I haven't run it against the repo.

The test compares each parsed result with `If(parse(<condition>), <then>, <else>)`. It uses `parse` on the condition rather than building `LogicalOr`/`LogicalAnd` by hand, so it doesn't depend on how those nodes are constructed. It covers conditions using `or`, `and`, `not` and a comparison. It also checks that a plain `if x else` still parses.

I left out chained conditionals (`1 if x else 2 if y else 3`) and `a or b if c else d`, since the issue doesn't say how those should behave.
